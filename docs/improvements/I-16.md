# I-16 — Slash commands wrapping the CLI's one-shot verbs

- **Improvement ID:** I-16
- **Version:** 0.10.0
- **Date:** 2026-07-29
- **Status:** ✅ DONE (552 tests; live-verified).
- **Related work:** Sits beside doctor.py and submit.py in codeblox-builder; consumes the viewer ops added in I-12 through I-15.

## Objective

Give the agent one-keystroke access to the three CLI operations that recur throughout a build loop, without duplicating what codeblox-builder already owns.

## Approach

Three commands, namespaced under `/codeblox:` so they group in the menu and cannot collide: `clear`,
`view` and `doctor`. Each is a single `!` pre-execution line, so the CLI call happens while the
prompt expands rather than after a model turn decides to make it.

Scope is set by what is *not* here. No `/box`, `/sphere` or `/cylinder`: every invocation pays a
fresh WS handshake and re-downloads the whole world snapshot, so one shape per process is precisely
the slow path `build.py` exists to avoid, and a command would teach the habit. No `/build` —
`codeblox-builder` owns plan→batch, and a second entry point is how the two drift. No `/info` (5 KB
of contract JSON nobody acts on) and no `/remove --id N` (you never know a part id by hand).
`/codeblox:clear` does not confirm: it is destructive and there is no undo, but the operator typed
the command name, and a prompt after that is theatre.

The commands must not hard-code `clients/codeblox/bin/codeblox.exe` — `resolve_codeblox.py` exists
so a PATH-installed binary beats a stale repo build, and bypassing it reintroduces exactly the
failure that invariant was written for. No existing script forwards an arbitrary verb, though:
`submit.py` runs batches and `doctor.py` preflights. Hence one new flagless script, `cli.py`, that
resolves the binary and forwards its whole argv verbatim.

Routing through a skill script rather than the binary path also settles the permissions question:
`.claude/settings.json` already allowlists `Bash(.venv/Scripts/python .claude/skills/*)`, so the
commands need **no new permission entries**. That is what keeps them fast, and it is why the venv
interpreter path is written out literally — a `[ -x … ] &&` prefix to pick `Scripts` vs `bin` would
fall outside the allowlist pattern and restore a prompt on every call.

Two deviations from the approach, both discovered while writing it.

The plan said `cli.py` would take `--bin`. It takes nothing: `rc.find` already reads `$CODEBLOX_BIN`,
so a flag would have been a second spelling of a path the resolver already honours — and a script
that parses *any* flag of its own has to decide which flags are the CLI's, which is precisely the
bug I-1 fixed one layer down. Flagless makes that decision structurally impossible.

The SKILL.md note was planned as a bare "cli.py exists". Writing it surfaced a real inconsistency
worth naming instead: §"Running the scripts" forbids writing a path to the binary, yet §7 quotes
`codeblox view 4` bare, which silently assumes `$PATH`. On this machine `codeblox` is **not** on
`$PATH` — those examples would fail as written. The note now says so and points at `cli.py`.

## Verification

`$VENV/python -m pytest .claude/skills/codeblox-builder/tests/` — 277 passed, 1 skipped (267 before;
10 new). `npm test` — 9 files, 126 tests, untouched by this phase and green.
`mirror_skill.py --check` — both mirrors up to date, 20 files each.

Live, against the running server:

```
doctor.py                 [ok  ] binary / auth / world                        exit 0
cli.py box --at 0,0,0 …   sent 1 command(s): 1 added …  ids: [9]              exit 0
cli.py view 4             sent 1 command(s): 0 added, 0 removed               exit 0
cli.py view rotate on     sent 1 command(s): 0 added, 0 removed               exit 0
cli.py clear              sent 1 command(s): … cleared=true                   exit 0
cli.py view bogus         unknown view subcommand "bogus": want a preset …    exit 2
cli.py                    cli: needs a codeblox verb, for example `clear` …   exit 2
```

`view bogus` is the one that mattered: the message is the CLI's own, verbatim, with no Python
traceback wrapped around it — which is the whole reason this script validates nothing.

The negative path was exercised rather than assumed. With `npm run dev:stop` run first, `doctor.py`
reported `[FAIL] auth  connect to ws://127.0.0.1:7799 … actively refused it` and exit **4**, then
returned to three `[ok  ]` rows after `npm start`. That is the failure this phase was prompted by —
a browser showing `ERR_CONNECTION_REFUSED` on 5173 because nothing was listening — and it now has a
one-command answer that names the remedy.

Registration confirmed: the three commands appear to the host as `codeblox:clear`, `codeblox:view`
and `codeblox:doctor` with the descriptions from their frontmatter.

Not verified: that the browser visibly snaps to preset 4 or starts rotating. The relay was confirmed
to the CLI boundary; the camera math is unit-tested in I-13 and no headless browser runs in this
repo. Also unverified on POSIX — the commands hardcode `.venv/Scripts/python`, which is a Windows
path (see the Approach for why a runtime branch was rejected).
