# I-8 — Plans declare their subject's real size, and build.py refuses a mismatch

- **Improvement ID:** I-8
- **Version:** (pending)
- **Date:** (pending)
- **Status:** 🚧 IN PROGRESS
- **Related work:** depends on the exhaustive aabb() from R1

## Objective

Convert the model's latent knowledge of real-world dimensions into a checked constraint.

## Approach

The failure was silent and systematic rather than occasional. At 2 cm blocks, `builds/tesla-model-s.json` is 1.16 m long against a real 4.97 m, `car.json` is 0.92 m, `bear.json` is 0.96 m tall, and `golden-gate-bridge.json` is 22.4 m against 2737 m. Nothing anywhere in the pipeline knew what a block was worth, so there was no value any check could have compared against — the model converted in its head, or did not.

Three parts, and the order matters.

**A plan declares its subject.** `subject.mm` is the real-world size in millimetres, in the protocol's own `x, y, z`. Everything converges on millimetres because a block is a whole number of them at any sane block size, so `to_blocks` is exact integer arithmetic rather than a float that rounds two ways. The field is **optional but validated when present**: every plan written before this improvement is still valid, and a build with no real-world referent has nothing to declare — but a malformed `subject` is refused, because it would silently disable the gate it was written to enable, which is worse than not declaring at all. `from_lwh` exists for one reason: a spec sheet prints length first and height last, transposing those is the single likeliest way to declare a subject wrong, and it fails quietly because all three numbers stay plausible.

**`build.py` refuses a mismatch before the first block is sent.** `check_scale` runs ahead of `validate`, so the plan is measured against its declaration before the bounds gate and before the server dry-run. This is the same guarantee I-5 built the staged gate for, and for the same reason: `remove` takes an id, not a region, so there is no partial undo — a build discovered to be four times too small after 37 parts have landed has to be cleared wholesale. The extent is measured from the **expanded** commands, never from the shape calls, because a generator's arguments are not uniformly lengths.

The **ratio triple** is what makes the failure actionable, and it separates two cases with opposite remedies. A uniform miss is arithmetic: every axis is out by the same factor and one rescale repairs it, so the message points at `dims.py fit`. A proportion error is a geometry mistake, and offering the rescale there would be *actively harmful* — one factor cannot repair three ratios, and applying one anyway yields a correctly-sized wrong shape which then passes this very gate. So that envelope names the outlier axis and says to correct the geometry. The gate imports `to_blocks`/`ratios`/`spread` from `dims.py` rather than reimplementing them, so the check and the repair cannot disagree about what the right size is.

Tolerance is 10% per axis with a **one-block floor**. The floor is not slack: `to_blocks` rounds to the nearest block, so a subject can be half a block out at each end through no fault of the plan, and without it small subjects would fail for being quantised.

`subject_exceeds_world` is checked first, because otherwise the only thing a builder is told is that the build is too small — true, and unachievable. It names the largest subject that fits at 1:1 and the `world.extent` to raise, since in this project a world is configured in metres and a 2 km subject means a bigger world, not a scale model. On the Golden Gate at 1:1 it asks for at least 1368.5, which is where P-11's `extent 1400` comes from.

**`dims.py` turns declarations into coordinates and repairs plans that missed.** The conversion is one division, which is exactly why it belongs in a script: the failure is never the arithmetic, it is forgetting that a block is not a metre. `fit` scales a plan to its own declaration, and `scale_command` scales **both corners** and derives the size as `max - min`, never `at` and `size` independently — rounding them separately is what opens a one-block seam at every joint, so two parts that shared a face in the plan stop sharing one in the world. `rescale` expands shape calls to raw commands first, because `segments`, `steps` and `thickness` are not lengths and would all be scaled wrongly; the result is still a faithful record, just no longer parameterised. It scales about a grounded, footprint-centred point, so a fitted build stays on the floor instead of having its height scaled off it. `anchors` reports five human-scale references rather than a catalogue of objects, which would be unbounded and would go stale — a model that knows a storey is 3 m can size a building it has never seen.

Nothing here writes down the block size. `world.digest` derives `blocksPerMetre` from the contract and returns `None` rather than inventing a number when the contract does not say, `doctor.py` states it on the rung that already had the contract in hand, and `stage_line` reports each landed stage in metres. Changing `config.yaml` changes every one of them with no edit.

Two notes on what was inherited. The `dims.py` in the tree at the start of this phase had never been executed; its `factor` was a harmonic mean written as a chained `and` — for a build twice its declared size it scaled *up* by two rather than halving. That was the first red. And `world.fetch(refresh=True)` passes `--refresh` to a CLI verb that does not accept it, so a refresh is a usage error and `doctor.py` can report a stale cached contract; found while verifying this phase, left for its own item.

## Verification

`pytest` — 210 passed, 1 skipped for `codeblox-builder` (was 162). `npm test` — 74 passed, unchanged; no JavaScript was touched.

Live against a running server, which is what the unit tests cannot show. `builds/tesla-model-s.json` with a real Model S declared (4970 x 1964 x 1445 mm, through `from_lwh`) was refused at exit 5 — `subject declares [98, 72, 248] blocks, plan builds [24, 16, 58]`, ratio `[0.245, 0.222, 0.234]`, classified uniform and pointed at `fit`. `dims.py fit` returned `[102, 68, 248]`, the gate passed on the fitted plan, and the build landed: 37 parts across 5 stages, a 4.96 m car in the world.

That live run is also what caught the one defect the tests had missed: the metre column was a fixed width and `2.04×0.68×3.26 m` overran it, printing `3.26 m620ms`. The column now holds its width when the label fits and yields when it does not, pinned by a test at world-extent magnitude.

The guard worth naming is `test_two_parts_sharing_a_face_still_share_it_after_scaling`. It is the only test that would catch `scale_command` regressing to rounding `at` and `size` independently, and the symptom of that regression is not a failure anywhere — it is a one-block gap at every joint in a build that otherwise passes every check.
