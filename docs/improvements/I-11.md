# I-11 — One source for codeblox-builder, a sync script, and a test that fails on drift

- **Improvement ID:** I-11
- **Version:** 0.8.0
- **Date:** 2026-07-27
- **Status:** ✅ DONE (488 tests; live-verified).
- **Related work:** the drift accumulated across P-7, P-9 and P-10

## Objective

Make mirror staleness impossible to ship unnoticed: generate both mirrors from the one source and fail a test when they drift, then sync them.

## Approach

`.claude/skills/codeblox-builder/` is the one source; `.codex/` and `.agents/` are copies of it.
Their frontmatter is byte-identical to the source's, so the mirrors need **no per-host adaptation** —
every current difference is drift, not adaptation, which is what makes a plain copy plus an equality
check sufficient. (Confirming that assumption still holds is the first step of the work; if any
mirror ever needs to differ, this approach is wrong and the phase should stop and re-plan.)

Three parts:

1. **A sync script** that regenerates both mirrors from the source, so syncing is one command rather
   than a recursive copy someone assembles from memory.
2. **A drift test** that fails when a mirror does not match the source, wired into the suite that
   already runs on every change. This is the part that matters: the mirrors have gone stale after
   P-7, P-9 and P-10 precisely because nothing failed when they did. A sync script without the test
   would just be a fourth manual step to forget.
3. **Sync the mirrors**, which is what turns the new test green — currently ~1526 lines of drift plus
   three files absent from both mirrors (`dims.py`, `test_dims.py`, `test_doctor.py`).

**Resolved during the work: the mirrors stay committed.** Gitignoring them would make drift
impossible, which is the stronger guarantee — but a mirror exists precisely so another agent host can
read the skill straight from a checkout, and a generated-and-ignored mirror is absent exactly when it
is wanted. The drift test buys the same safety at the cost of one command, and unlike the honour
system it has now been shown to fail on a real edit.

Two things narrowed the work once the source was mapped:

- **Only `codeblox-builder` is mirrored.** The `dev-phase-*` skills under `.claude/skills/` are
  chore-track tooling for this repo's own workflow, not product shipped to an agent host, and neither
  mirror has ever carried them.
- **`.agents/rules/` is out of scope and left untouched.** Those 12 files have no source anywhere in
  the repo — `.claude/` tracks only `settings.json` and `skills/` — and their names no longer match
  the global rule set they appear to have been copied from. They are orphaned, not drifted, and
  deleting tracked files that look like personal content is not this item's call.

## Verification

488 tests: 95 vitest (4 new), 112 Go unit, 24 Go e2e, 257 pytest (+1 skipped).

The drift test was watched failing before the sync existed — it named all 10 drifted files and the 3
missing ones per mirror, which is the failure message that makes it useful rather than merely red.

The mechanism was then verified end to end rather than assumed: appending one line to
`.codex/…/scripts/world.py` made the suite fail naming exactly `scripts/world.py`, and
`npm run sync:skills` reported `1 written` and returned it to green. A drift test that has never been
seen catching drift is an assumption, and this item exists because three phases of assumptions went
unnoticed.

The mirrored suites were run directly, not just compared: `pytest .codex/skills/codeblox-builder/tests`
passes 257 (+1 skipped), identical to the source. Byte equality proves the copy; running it proves
the copy is usable, which is the thing a mirror is for.

A `--check` mode was written and then removed before finalizing. `npm test` already runs the drift
test on every change, so a second way to ask the same question would be one more untested path to
keep honest.
