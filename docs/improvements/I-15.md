# I-15 — Teach world.py and SKILL.md the viewer ops

- **Improvement ID:** I-15
- **Version:** 0.9.0
- **Date:** 2026-07-28
- **Status:** ✅ DONE (542 tests; live-verified).
- **Related work:** the F-2 allowlist rationale; the P-14 mirror test

## Objective

Let a plan stage carry a viewer op through the existing raw-op passthrough, and keep F-2's guarantee intact — an op missing from the allowlist must still raise AnchorError rather than bypassing the bounds and scale gates. Land last, so SKILL.md describes only behaviour that already exists.

## Approach

`world.py`'s no-geometry frozenset gains the five names. That list is a hand-maintained mirror of
the JS sets, and it is the real drift risk in this phase — but the F-2 design holds: an op *missing*
from it makes `aabb()` raise `AnchorError` rather than silently returning `None` and bypassing the
bounds and scale gates. That raise stays, and a test pins it.

No new script. A `view.py` would emit a JSON literal and remove no probabilistic failure —
`world.py`'s `digest()` already reflects the published ops and their fields back to the agent, and
`build.py`'s `expand_part` already passes any dict carrying an `op` through verbatim, which is how
`{"op":"clear"}` works in a stage today. So a plan can express `{"op":"view","n":1}` in a stage with
no new machinery, and `check_stage`'s "at least one part" requirement is satisfied by a raw op.

`SKILL.md` gains a short section on directing the camera: the five ops, `codeblox view` as the
imperative path and a plan stage as the declarative one, the rule that viewer ops go **last** when
the intent is to review a finished build, and the fact that a viewer-only batch reports `0 added, 0
removed` — which is success, not failure, and would otherwise be read as one.

This phase lands after the other three so the documentation describes only behaviour that already
exists — the failure mode P-13 and P-14 were both about. Then propagate the mirrors:
`$VENV/python scripts/py/mirror_skill.py --check` to confirm the drift, then without `--check` to
fix it, and commit the mirrors on the chore track. (P-14's vitest drift test is gone — mirroring
left the product surface entirely, so nothing in `npm test` will remind you.)

The approach's one deviation: it said the frozenset "gains the five names". Splitting them into a second
set and taking the union instead costs one line and keeps this mirror shaped like the thing it mirrors —
`protocol.js` holds `CONTROL_OPS` and `VIEWER_OPS` apart deliberately, and a future audit compares set to
set rather than picking nine names apart by eye. `aabb()` only ever reads the union, so nothing here routes
on the distinction.

## Verification

`$VENV/python -m pytest .claude/skills/codeblox-builder/tests/` — 267 passed, 1 skipped, 9 new
(5 of them from the widened parametrisation). `npm test` — 9 files, 126 tests, untouched by this phase
and green.

**F-2's guarantee, checked rather than assumed.** Live, against the running server:

```
{"op":"zoom","factor":2}    submit: no anchoring rule for op 'zoom' …          exit 5
{"op":"view","n":99}        submit: server rejected … n must be 1..6           exit 6
```

Exit 5 is the client refusing an op it cannot measure — the raise this phase had to not weaken. Exit 6 on
`view 99` is the other half of I-14's design still holding: the client forwards it because `n` is `int+`,
and the server, the only party that knows there are six presets, refuses it.

**The declarative path, end to end.** A two-stage plan (a 4-block box, then a stage of `view 4` + `grid on`)
dry-ran clean at 3 commands and then landed:

```
stage 1/2  mass         1 cmd    ids [1]         0.08×0.08×0.08 m    350ms
stage 2/2  review       2 parts  no ids
```

That run corrected a claim the approach had written into `SKILL.md` before it was checked. The approach
predicted a viewer-only batch reports `0 added, 0 removed`; nothing prints that string. `build.py` prints
`no ids` on the stage line and `submit.py` prints `sent 1 command(s)` with `addedIds: []`. The section now
documents the two forms that actually appear — which is the whole reason this phase was sequenced last, and
it earned its place on the one sentence written from memory rather than from output.

The doctor line also confirmed the server was not stale (`ops … grid, hud, reframe, … rotate, … view`)
before any of the above was trusted — the failure mode where an op exists in `protocol.js` but not in the
process serving it.

Not verified: that the browser visibly snaps to preset 4. The relay was confirmed to the CLI boundary and
the camera math is unit-tested in I-13; no headless browser runs in this repo.
