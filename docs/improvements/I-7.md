# I-7 — Native ellipsoid and tube ops

- **Improvement ID:** I-7
- **Version:** (pending)
- **Date:** (pending)
- **Status:** 🚧 IN PROGRESS
- **Related work:** the generators in the SKILL.md phase are built on these

## Objective

Expose the rounded, orientable vocabulary the renderer could already draw, without introducing rotation into the coordinate space.

## Approach

The prompting observation: the model used `sphere` for car wheels, bear paws and human hands. `builds/bear.json` is 17 spheres out of 17 parts; `builds/car.json` is 12 spheres to 11 boxes. That is not a taste problem — it is the only rounded primitive that can be placed at all.

`World._compose` composes every instance matrix with `IDENTITY_QUAT`, so **no part is ever rotated**, and `cylinder`'s axis is y. A wheel is a cylinder about x, which the vocabulary could not express. Meanwhile `sphere`'s `r` is a scalar `int+`, so it is always a perfect sphere — a squashed one, which is what a paw or a hood actually is, was equally unavailable. Faced with that, `sphere` is the correct choice from a wrong menu. (`builds/tesla-model-s.json` shows the alternative: its wheels are three crossed boxes plus a hub, and they still read badly.)

Two additions, both exploiting capability the renderer already had.

**`ellipsoid`** — `at` = centre, `size` = full extent. `geometry.js` already built a unit `SphereGeometry(0.5, …)` and `_compose` already applies a **fully non-uniform** scale from `part.size`, so the renderer could draw any axis-aligned ellipsoid the whole time; only the schema refused to describe one. `toPart` therefore returns `kind: 'sphere'` — it reuses the existing geometry *and* its `InstancedMesh`, so this costs no new draw call and no `GEOMETRY_KINDS` entry. Eight lines of protocol, zero renderer.

**`tube`** — `at` = centre, `r`, `h`, `axis`. A scale cannot reorient an axis, so this needs real geometry, but it does not need rotation *at runtime*: `cylinder().rotateZ(π/2)` and `.rotateX(π/2)` bake the orientation into the vertex buffer at construction. `toPart` permutes the size triple onto the named axis and selects `cylinder` / `cylinder_x` / `cylinder_z`. `_compose` stays `IDENTITY_QUAT`, and — the point of doing it this way — the permuted size **is** the world AABB, so `partAabb` stays exact and no conservative-bounds arithmetic enters `protocol.js`, `World.js`, or `world.py`.

Both are **new ops rather than new fields**, which is forced rather than stylistic. `contract.go:139-148` iterates the published field spec and errors on any declared field absent from a command, pinned by `contract_test.go:112`. So adding `axis` to `cylinder` would have broken every cylinder already written — all 14 in `golden-gate-bridge.json`, all 9 in `white-house.json`, and the e2e `world_test.go:157`. A new op costs nothing: the CLI is schema-driven, `checkField` returns nil for an unrecognised field *type* (`contract.go:191-195`), and no test asserts the op set exhaustively.

A general 90°-snap rotation field was considered and rejected. For a box or an ellipsoid a 90° rotation is the same shape with a permuted size, so it buys nothing; it only matters for cylinder-like forms, and for those a named `axis` is cheaper, keeps `_compose` identity, and is far easier for a model to emit correctly than one of 24 orientations. Arbitrary rotation is deferred for a harder reason: it makes `at`/`center` fractional and forces the conservative `|R|·half` AABB in four places, which ends the integer-block invariant that `partAabb`, `withinBounds` and Go's `asInt` all rest on.

A native `wedge` was also declined. The two cases that argue for it — the golden-gate cable staircase and the Tesla roofline — are answered better elsewhere: a suspension cable is a catenary, not a ramp, and at 253 blocks a stepped roofline has ~4-block risers, i.e. 8 cm. Stepping artefacts are absolute, not relative, so fixing the scale (P-9) removes most of what motivates a wedge.

## Verification

`npm test` — 74 passed (was 68).

The guard worth naming is `has a geometry for every kind the protocol can produce`. `toPart` invents kind strings and the engine builds one layer per kind; a kind in one and not the other is a part the server accepts and nothing draws — silent, and invisible to every other test. It asserts both directions: every kind `expand()` can emit is in `GEOMETRY_KINDS`, and `makeGeometries()`'s keys are exactly that list.
