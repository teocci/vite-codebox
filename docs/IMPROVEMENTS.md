# Improvements

Internal index of improvement items (`I-N`). Status is tracked inline in **Notes** — in progress
carries no done-marker; finalized appends `✅ Done in vX.Y.Z.` Detail files: `docs/improvements/`.

| ID | Idea | Notes |
|----|------|-------|
| I-1 | Per-verb flag validation | One shared `FlagSet` gave all 14 flags to all 8 verbs, so a foreign flag parsed clean and was ignored; `exec batch.json --json` dropped `--json` and exited 0. Per-verb surfaces + positional guard + validation before the keyring opens. Framework evaluated and declined — stdlib won all three rubrics. Detail: `docs/improvements/improvement-1.md`. ✅ Done in v0.5.0. |
| I-2 | Machine-readable failure contract | Every failure exited 1, so a wrapper could not tell "not authenticated" (re-auth) from "unreachable" (retry) from "bad material" (re-plan). Taxonomy 0/2/3/4/5/6 via a `Failure` wrapper whose innermost classification wins and survives `%w`; `--json` failures now emit a `{ok,code,exit,detail}` envelope on stderr; bare `codeblox` exits 2 on stderr. Detail: `docs/improvements/improvement-2.md`. ✅ Done in v0.5.0. |
| I-4 | Split `App` along its two domains | `App` carries 9 public methods spanning unrelated concerns — credential lifecycle (`Login`/`Logout`/`List`/`Status`) and world building (`Exec`/`RunOne`/`RunBatch`/`Info`/`Materials`) — sharing only `Env`, the streams, and `Dial`. At the ~7–10 god-object ceiling. The seam is already drawn by `auth.go` / `build.go`: two types over a small embedded struct. Fold in `App.Status`, which is 50 lines. Hygiene, not a defect — deliberately deferred until after P-5 so it does not tangle with new work. Detail: `docs/improvements/improvement-4.md`. ✅ Done in v0.6.0. |
| [I-5](improvements/I-5.md) | Staged build workflow for `codeblox-builder` | The skill had a pipeline and no workflow: one flat batch, one line of output, nothing about order. `submit.py` dry-runs only its own batch, so a bad material in the last stage of five surfaced after four had landed — and `remove` needs ids, so there is no partial undo. New `build.py` takes a declarative stage plan, gates **every** stage before sending the first, then lands them beat by beat with progress and pacing off the real settle time (each batch is one `DropAnimator` beat). Openings are composed, not carved — this engine has no boolean subtraction. Undo ledger considered and declined. Detail: `docs/improvements/I-5.md`. 🚧 In progress. |
| [I-6](improvements/I-6.md) | Teach the viewer what a "build" is | Build the white house, inspect it, build the bridge — the camera never moved. Only `world.onClear` re-engaged it, and even then it framed *all* parts, so two builds 500 blocks apart became two specks. The root cause was conceptual: the viewer saw a stream of parts and could not know which were the new thing, and no timing heuristic recovers that (the gap *within* one build is unbounded). New field-less `build_begin` control op, relayed by the server, sent by `build.py` ahead of stage 1; the viewer groups a build's ids and frames that sphere. Zero Go changes — the CLI is schema-driven. Plans moved out of the repo root into a gitignored `builds/`. Detail: `docs/improvements/I-6.md`. 🚧 In progress. |
| I-3 | End-to-end test harness | Unit tests call Go functions and never spawn a process, so stream separation and exit codes were uncovered — the two things P-5's wrappers branch on. `clients/codeblox/tests/` drives the built binary behind `//go:build integration`, hermetic (temp home, file backend), skipping when no server listens. Detail: `docs/improvements/improvement-3.md`. ✅ Done in v0.5.0. |
| [I-7](improvements/I-7.md) | World._compose already applied a fully non-uniform scale to a unit sphere and the schema simply refused to describe one (sphere.r is a scalar). ellipsoid reuses the sphere geometry and its InstancedMesh — no new draw call. tube carries its axis in one of three baked geometries rather than a per-instance quaternion, so parts stay axis-aligned and every AABB stays exact. Both are new ops, not new fields: the Go client requires every declared field to be present, so widening cylinder would have broken all 23 cylinders already in builds/. | 🚧 In progress. |
| [I-8](improvements/I-8.md) | A plan now carries subject.mm; build.py measures the expanded plan's own AABB and refuses a deviation before the first block is sent — which matters because remove takes an id, so there is no partial undo. The ratio triple separates a uniform scale error (mechanically repairable by dims.py fit) from a proportion error (not). subject_exceeds_world names the extent that would fit at 1:1. New dims.py converts real dimensions to blocks and rescales a plan by scaling min and max corners, never at and size independently — the latter opens a one-block seam at every joint. | 🚧 In progress. |
| [I-9](improvements/I-9.md) | The castle example (size [40,14,40] = an 80 cm castle) and the bridge advice (a 16 cm deck) taught 1 block = 1 m by worked example; both are deleted. The metre value stays out of the prose — SKILL.md's own rule is that runtime values come from the server, so world.py reports blocksPerMetre and the model declares subject.mm instead of converting. 'Prefer few large parts / 40x the cost' is factually wrong (one InstancedLayer per kind:family, so forty boxes of one material are one draw call) and is replaced with the real cost model and per-subject budgets. New wheel/taper/dome generators over the native ops. | 🚧 In progress. |
| [I-10](improvements/I-10.md) | CameraDirector's fitting math is already scale-free, but the camera's far plane is a literal 5000: a 2737 m subject sits at a fit distance of ~4214 m with its far corner at ~5584 m, so it clips. Grid divisions are extent*2/gridStep with gridStep pinned at 1 m, which at extent 1400 is 2800 divisions and reads as a solid grey sheet. Both now derive from WORLD.extent, plus a logarithmic depth buffer to hold precision at any range. | 🚧 In progress. |
