# F-3 — `world.py` sends `--refresh` to a verb that rejects it, and documents a cache `info` never reads

- **Fix ID:** F-3
- **Version:** 0.8.0
- **Date:** 2026-07-27
- **Status:** ✅ DONE (488 tests; live-verified).
- **Related work:** surfaced during P-9 verification; the stale-server half was resolved in P-10

## Symptom

`world.fetch(refresh=True)` runs `codeblox info --json --refresh` and dies on `flag provided but not defined: -refresh`; the docstring also claims `info` serves from the contract cache, which it does not.

## Root cause

Two independent mistakes on the Python side, both asserting things about `codeblox info` that were
never true.

The flag: `buildVerbs` in `clients/codeblox/internal/command/dispatch_build.go` declares each verb's
surface beyond the common five, and its entry for `info` is `func(*buildFlags) {}` — no verb-specific
flags at all. `--refresh` is registered only on `materials`. Since I-1 made an unknown flag a hard
error rather than a silent no-op, `codeblox info --refresh` exits 2 instead of being ignored.

The cache: `Info` (`internal/command/build.go`) calls `a.session(...)` directly and never goes
through `contractFromCache`, which is the only reader of `~/.codeblox/world_info.json`. So `info`
*always* dials the server — it is the write side of that cache, never the read side. A `--refresh`
flag on `info` would therefore be meaningless even if it parsed.

`world.py`'s `fetch` docstring states both — "the CLI caches the contract … and serves reads from
there, so this is cheap to call repeatedly. `--refresh` forces a fetch" — and neither half holds.

The consequence is the reason this is worth fixing rather than deleting a flag: the docstring made a
**stale server** look like a **stale cache**. During P-9 the server was genuinely running old code
and publishing 8 ops without `ellipsoid`/`tube`; the recorded diagnosis was a stale contract cache,
and the recorded remedy was deleting the cache file by hand. The real remedy was a server restart,
which is what P-10 confirmed. A wrong mental model of where the contract comes from cost a
misdiagnosis, so the fix has to correct the model, not just the argv.

## Fix

Deleted rather than repaired. `--refresh` is gone from `world.py` entirely — the `fetch` parameter,
the argv append, and the CLI flag — because there is nothing for it to do: `info` is already always
live. The alternative, registering `--refresh` on the `info` verb, was rejected: it would only mean
something if `info` became cache-first, and `info` dialling the server is exactly what makes it
`doctor.py`'s liveness check. Making the flag work would have broken preflight to satisfy a flag
nobody needed.

The docstring now states what `info` actually does — dials every call, writes the cache, never reads
it; only `materials` reads it — and carries the operational consequence explicitly: **if the contract
looks out of date, the server is stale, not the cache; restart it.** That sentence is the fix for the
misdiagnosis, since the argv was only ever the symptom.

No production caller was affected: `build.py`, `dims.py`, `doctor.py` and `submit.py` all call
`world.fetch(binary)` with no refresh argument. The only callers were `world.py`'s own CLI flag and
the test that locked the defect in.

## Files changed

| File | Change |
|---|---|
| `.claude/skills/codeblox-builder/scripts/world.py` | `fetch` loses its `refresh` parameter and the argv append; the CLI loses `--refresh`; the module and function docstrings describe the caching `info` actually has, and name a stale server as the real cause |
| `.claude/skills/codeblox-builder/tests/test_world.py` | `test_refresh_is_passed_through` deleted; replaced by one test that the option is not offered and one asserting `fetch`'s argv by equality |

## Verification

257 pytest in `codeblox-builder` (+1 skipped), up one from 256 — one misleading test removed, two
added. Full product suite green at release: 488 tests (95 vitest, 112 Go unit, 24 Go e2e, 257 pytest);
it stood at 484 when this phase finished, before P-14 added the four mirror-drift tests.

The replacement test asserts `fetch`'s argv by **equality** (`['codeblox', 'info', '--json']`) rather
than membership. That distinction is the point: the deleted test asserted `'--refresh' in argv`, which
verified only that the mock had received what the code sent, never that the CLI would accept it — so
it stayed green for the entire life of the defect. An equality assertion fails the moment an argument
the verb does not accept is added.

Live: `world.py` prints the digest against a running server, and `world.py --refresh` is now refused
by argparse with a usage line naming the valid options, instead of being forwarded to a verb that
rejects it.
