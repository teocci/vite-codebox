# F-2 — world.aabb() returned None for fill, bypassing the bounds gate

- **Fix ID:** F-2
- **Version:** 0.7.0
- **Date:** 2026-07-27
- **Status:** ✅ DONE (483 tests; live-verified).
- **Related work:** prerequisite for the plan-AABB measurement in the scale gate

## Symptom

An out-of-bounds `fill` sails through the skill's client-side bounds gate and is only refused by the server, mid-build — where there is no partial undo, so the world is left half-built. The gate reports the batch as clean.

## Root cause

`world.aabb()` matched `box`, `sphere` and `cylinder` and then `return None` as a fall-through. `None` is the module's signal for "occupies nothing", used for control ops like `clear` and `remove` — so `out_of_bounds()` treated every op it did not recognise as having no geometry, and passed it.

`fill` is a published part op (`protocol.js:21`, `OP_SCHEMA:37-46`) and had no case, so it inherited that default. Both callers are affected: `submit.check_bounds` and `build.check_bounds`.

The failure mode is the worst available one. Bounds are enforced server-side only — deliberately, since the published contract types fields and does not describe geometry — so the pre-gate is the only thing standing between a bad `fill` and a half-built world. And `build.py` gates the whole plan before sending precisely because `remove` needs ids, so a mid-build rejection can only be unwound with `clear`.

The general defect is the fall-through, not the missing `fill` case: any op added later inherits the same silent pass. That matters immediately, because P-8 adds two (`ellipsoid`, `tube`) and P-9 builds a plan-extent measurement on top of the same function — an op invisible to `aabb()` would also be invisible to the declared-size check, silently shrinking the measured build.

## Fix

Invert the default. An explicit `CONTROL_OPS` allowlist returns `None`; everything else must have a case; anything left raises.

```python
CONTROL_OPS = frozenset({'remove', 'clear', 'world_info', 'build_begin'})
```

Cases added for `fill` (inclusive cells, so the extent is `|to - from| + 1` — off by one in the opposite direction from every other op), and for `ellipsoid` and `tube` ahead of P-8. A `_centred` helper carries the three centre-anchored ops so the convention is written once.

The raise is a new `AnchorError(WorldError)` rather than a bare `WorldError`, because the two mean different things to a caller and the skill's exit taxonomy distinguishes them: a failed fetch is a server problem (exit 4), an op that cannot be measured is a command rejected before anything was sent (exit 5). `submit.py` and `build.py` catch `AnchorError` **before** `WorldError` — subclass first, or the generic handler wins and a bad plan reports "the server is unreachable".
