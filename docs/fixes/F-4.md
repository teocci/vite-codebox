# F-4 — The HUD extent row overflows the panel at 1:1 scale

- **Fix ID:** F-4
- **Version:** (pending)
- **Date:** (pending)
- **Status:** 🚧 IN PROGRESS
- **Related work:** I-10 (P-11) — the same class of defect, viewer literals tuned for the 64 m world that shipped before it; the scale gate from I-8 (P-9), which is why the metre value must stay exact

## Symptom

The HUD's `extent` row carries both unit systems in one value. At the 1:1 scale P-9 made the point
of the project, the Golden Gate build renders

```
extent   136850×11350×136850 blk · 2737×227×2737 m
```

— 41 monospace characters in a single value. `.hud` sets `min-width: 15rem` but no `max-width`, so
the panel grows across the viewport. The failure appears only at the scales P-9 and P-11 exist to
make possible.

## Root cause

Two independent things, both dating from the 64 m world that shipped before P-11.

The row was written to carry both unit systems because at 64 m both triples were short and the
combined value still fit. P-9 and P-11 then made 1:1 builds the point of the project without
revisiting it — and since `BLOCK_SIZE` is `0.02` the block triple is **by construction** 50× the
metre triple, so once one is large the other is too. The two can never both be short again.

Underneath that, `.hud` has a `min-width` and no upper bound, so nothing stops a long value from
pushing the panel to any width. The row is what trips it; the missing cap is why there is no floor.

Same class as I-10: viewer literals tuned for a world size that no longer ships.
